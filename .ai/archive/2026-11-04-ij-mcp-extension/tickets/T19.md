## Goal

`wait_for_run` does not reply `wait: done` before the run history records the end of the process. The tool description states the header state on a timeout correctly.

## Non-goals

No change to `RunStore`, `RunHistoryService` or `runOutput`. No new tool parameter. No change to the poll interval or the 5 s grace value.

## Context

Source: user-accepted follow-ups at phase 5 end (brief from the orchestrator).

Problem 1. The process handler reports terminated a moment before `RunHistoryExecutionListener.processTerminated` (src/main/kotlin/pl/mario/intellij/mcp/RunHistoryService.kt:31) calls `store.terminated`. A poll in that gap gets `WaitVerdict.DONE`, so the reply shows `finishedAt=unknown` and a null exit code.

Recommended fix (logic change in RunWait.kt, so add a unit test):
- `waitVerdict` (src/main/kotlin/pl/mario/intellij/mcp/RunWait.kt:8) gets a last parameter `endRecorded: Boolean = true`. The default keeps the existing positional calls in RunWaitTest.kt compiling.
- New rule, right after `!processEnded -> WAIT`: when `!endRecorded`, return WAIT while `processEndedAtMillis` is null or `nowMillis - processEndedAtMillis < graceMillis`. After the grace, fall through to the existing rules, so a lost record never hangs the wait.
- The caller in `wait_for_run` (src/main/kotlin/pl/mario/intellij/mcp/RunControlToolset.kt:181, the `waitVerdict(` call near :229) passes `endRecorded = record == null || record.finishedAtMillis != null`, with `record = store.get(id)` read once per poll. A run with no record (started before the plugin loaded) never gets one, so it counts as recorded.
- Tests in src/test/kotlin/pl/mario/intellij/mcp/RunWaitTest.kt, same style as `endedWithoutTreeIsDone`: (a) ended, no tree, end not recorded, inside grace -> WAIT; (b) same after grace -> DONE.

Problem 2. The description at RunControlToolset.kt:179 says a timeout shows `state=running`. A timeout during the 5 s test-tree grace (and now also the record grace) shows `state=terminated`. Fix the text only: the header shows `state=running`, or `state=terminated` when the process ended but its test tree or end record is not ready yet.
