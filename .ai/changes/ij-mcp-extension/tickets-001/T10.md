## Goal

The decision about when `wait_for_run` stops waiting, and its timeout clamp, live in pure functions covered by JUnit 4 tests.

## Non-goals

- No IDE types, no tool (T11).

## Context

Plan: "Phase 4 > 1. Pure wait verdict" and "Critical Implementation Details" (timing). Contract, copied:
- `enum class WaitVerdict { WAIT, DONE, DONE_TREE_UNFINISHED }`.
- `fun waitVerdict(processEnded: Boolean, hasTestTree: Boolean, treeFinished: Boolean, processEndedAtMillis: Long?, nowMillis: Long, graceMillis: Long = 5_000): WaitVerdict`.
- `fun clampTimeout(requested: Int?): Pair<Int, Boolean>` sets the default to 300. Values below 0 become 0, and values above 1800 become 1800. The Boolean is true when the value was clamped.

Rules from Critical Implementation Details: a test run counts as done only when the process ended and the test root is no longer in progress. If the tree is still in progress 5 s after the process ended, return with the tree unfinished.

Settled here:
- Process not ended → WAIT. Ended, no tree → DONE. Ended, tree finished → DONE.
- Ended, tree unfinished: WAIT while `nowMillis - processEndedAtMillis < graceMillis`, else DONE_TREE_UNFINISHED. A null `processEndedAtMillis` means WAIT (the caller supplies the time it first saw the end).
- `clampTimeout(null)` is `(300, false)`.

`RunWaitTest` (JUnit 4; copy the style of `RunStoreTest.kt`), one assertion per case: running → WAIT; ended without tree → DONE; ended with unfinished tree inside grace → WAIT; after grace → DONE_TREE_UNFINISHED; ended with finished tree → DONE; `clampTimeout` default, negative, above max.
