## Goal

A pure Kotlin test-node model and formatter with no IDE types, which `get_run_output` and `wait_for_run` will both use, covered by JUnit 4 tests.

## Non-goals

- No IDE types and no `SMTestProxy` mapping (T8).
- No edits to `RunControlToolset.kt` or `RunHistory.kt`.

## Context

Plan: "Phase 3 > 1. Pure test-node model and formatter". Contract, copied:
- `enum class TestStatus { PASSED, FAILED, IGNORED, UNFINISHED }`.
- `data class TestNode(suite: String?, name: String, status: TestStatus, message: String?, durationMs: Long?)`.
- `enum class TestsDetail { problems, all }`. The lowercase names are the MCP parameter values.
- `fun formatTests(nodes: List<TestNode>, finished: Boolean, detail: TestsDetail): String`:
  - The counts line keeps its current shape: `tests: total=…, passed=…, failed=…, ignored=…, other=…, finished=…`.
  - Then one `suite <name>: <n> tests, failed=<f>, unfinished=<u>` line per suite that has a listed test.
  - Then one indented line per listed test: `FAILED|UNFINISHED|IGNORED|PASSED <suite>.<name> — <first message line>`.
- `problems` lists FAILED and UNFINISHED tests only. `all` lists every test.
- At most 1000 test lines are listed, followed by `... and N more`.

Settled here:
- Add `fun countTests(nodes: List<TestNode>, finished: Boolean): TestCounts` in `TestTree.kt`, and use it for the counts line. `TestCounts` is in `RunHistory.kt` (T4). `other` counts UNFINISHED nodes. T8 makes the store use the same function, so the store and the tools count the same way.
- The counts line text matches today's, `RunControlToolset.kt:194`.
- `<n>`, `failed=` and `unfinished=` count all tests of the suite, not only the listed ones.
- Suites appear in first-seen order; tests keep input order. Each test line follows its suite line, indented two spaces.
- A node with `suite == null` is shown as `<name>` alone, under the suite line `suite (root): …`.
- When `message` is null or blank, the test line ends after the name, with no ` — `.
- The 1000 cap counts test lines only. `N` is the number of listed tests that were cut.
- ktlint rejects lowercase enum entries. Put `@Suppress("ktlint:standard:enum-entry-name-case")` on `TestsDetail`.

`TestTreeTest` (JUnit 4, `org.junit.Test`; copy the style of `RunStoreTest.kt` from T4), one assertion per clause:
- `problems` hides PASSED and IGNORED.
- `all` lists every test.
- suite grouping and the suite line counts.
- 1000-line cap with `... and N more` (1001 failed nodes give `... and 1 more`).
- counts line unchanged in shape.
- message reduced to its first line.
