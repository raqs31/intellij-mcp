## Goal

`RunControlToolset` imports no `.impl.` class. `verifyPlugin` fails the build on internal API use. Tool replies and parameters stay the same.

## Non-goals

- No change to tool names, parameters or reply strings.
- No `KillableProcess.killProcess()` branch, no force-kill.
- No new tools, no test source set (Phase 2 adds it).

## Context

Plan: `.ai/changes/ij-mcp-extension/plan.md`, "Phase 1: Public API baseline" and "Public API Constraint". Never use `.impl.` classes, `*Impl` classes, or members marked `@ApiStatus.Internal/Experimental/ScheduledForRemoval` or `@Deprecated`. If no public API exists for a need, stop and set the ticket `blocked` with a question. Do not use internal API as a fallback.

1. Verifier (`build.gradle.kts`):
   - `build.gradle.kts:54` filters out `INTERNAL_API_USAGES` from `failureLevel`. Make it fail on all levels (`VerifyPluginTask.FailureLevel.ALL`).
   - Remove the comment at `build.gradle.kts:53`.
   - Keep `freeArgs` at `build.gradle.kts:52`.
   - Note: plan.md cites `:47-50`; the real lines are 52-54.

2. Console text (`RunControlToolset.kt`):
   - Remove `import com.intellij.execution.impl.ConsoleViewImpl` (`RunControlToolset.kt:3`).
   - `runOutput` (`:125`) picks the first `ConsoleViewImpl` at `:133`. Pick the first `ConsoleView` (`com.intellij.execution.ui.ConsoleView`) in `consoleChain` (`:175`) instead.
   - Replace `console.flushDeferredText()` / `console.text` (`:149-150`) with: `DataManager.getInstance().getDataContext(console.component).getData(CommonDataKeys.EDITOR)?.document?.text`, on the EDT. Use the `DataKey` overload; `getData(String)` is `@Internal`.
   - Before the read: if `console.hasDeferredOutput()` is true, wait at most 1 s for `console.performWhenNoDeferredOutput(Runnable)` (EDT-only). This makes the read a suspend step (for example a `CompletableDeferred` plus `withTimeoutOrNull(1000)`). If the wait times out, read the document as it is and add the line `console: pending output not flushed` to the reply.
   - `console.component` creates the editor if the tab was never shown, so call it on the EDT only.
   - No editor found (console disposed, or not a text console): return `no_text_console: executionId=… uses <chain>.`, as `:134` does today.
   - `get_run_output` (`:91`) keeps its reply format.

3. Stop (`RunControlToolset.kt`):
   - Remove `import com.intellij.execution.impl.ExecutionManagerImpl` (`:4`) and the call `ExecutionManagerImpl.stopProcess(...)` at `:79`.
   - On the EDT: `handler.putUserData(ProcessHandler.TERMINATION_REQUESTED, true)`.
   - Then launch off the EDT on `Dispatchers.Default`, without waiting: unless `handler.isProcessTerminated`, call `handler.detachProcess()` if `handler.detachIsDefault()`, else `handler.destroyProcess()`.
   - `stop_requested: executionId=…` returns at once. The other replies at `:75-77` stay the same.

Decisions:
- Innermost ConsoleView, not the first one: BaseTestsOutputConsoleView implements ConsoleView, so the first one in a test chain is the wrapper. The old code took ConsoleViewImpl, which is the inner console. See Comments.
- Detached stop scope is CoroutineScope(Dispatchers.Default). A child of the tool call would make the call wait for the stop. GlobalScope needs the DelicateCoroutinesApi opt-in. A service scope needs a plugin.xml change outside files.
- The "console: pending output not flushed" line goes directly after the "--- console: N of M lines" header line.
- ProcessHandler.TERMINATION_REQUESTED is not deprecated (javap: the @Deprecated member is SILENTLY_DESTROY_ON_CLOSE; @Experimental is getNativePid).
Open: Manual Phase 1 checks in runIde (console text for an app run and a JUnit run, and a user stop in the Run tab) are not done. They need a human. The innermost-ConsoleView choice is part of the JUnit-run check.
