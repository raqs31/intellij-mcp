## Goal

`get_run_output` shows the suite-grouped test view from `formatTests`, picked by a `tests` parameter. A new `get_test_results` tool returns one test's status, duration, message, stack trace and own output.

## Non-goals

- No `wait_for_run` (Phase 4), no `list_run_history` (Phase 5).
- No edits to `TestTree.kt` (T7) or `RunHistory.kt` (T4).
- No `SMTestProxy.getStartTimeMillis`/`getEndTimeMillis`; they are `@Internal` and `@Experimental`.

## Context

Plan: "Phase 3 > 2. SM tree mapper and the tests parameter" and "3. get_test_results tool", plus "Public API Constraint". Read `src/main/kotlin/pl/mario/intellij/mcp/TestTree.kt` (T7) for `TestNode`, `TestStatus`, `TestsDetail`, `formatTests`, `countTests`.

Mapper and parameter, copied:
- `SMTestProxy` leaves map to `TestNode`, with the same ignored-before-defect rule as today.
- `get_run_output` gets `tests: TestsDetail = TestsDetail.problems`.
- `testSummary` is replaced by `formatTests`. Stack traces leave the default output, and `get_test_results` returns them.
- The `@McpDescription` names `tests` and points to `get_test_results` for stack traces and test output.

Settled here for the mapper:
- Leaves are `isLeaf && !isSuite` from `root.allTests` (today `RunControlToolset.kt:186`). Status: `isIgnored` → IGNORED; else `isDefect` → FAILED; else `isPassed` → PASSED; else UNFINISHED.
- `suite` is the parent name unless the parent is `SMTestProxy.SMRootTestProxy`, as `qualifiedName()` at `RunControlToolset.kt:207` does. `message = errorMessage`, `durationMs = duration` (public `getDuration()`).
- Put the mapper as `internal fun SMTestProxy.toTestNodes(): List<TestNode>` in `RunHistoryService.kt`. Change `countTests(root)` there (T5) to `countTests(root.toTestNodes(), !root.isInProgress)` from `TestTree.kt`, so store and tools count the same way.
- Remove `testSummary`, `MAX_FAILED_TESTS` and `MAX_STACK_LINES` once unused (`RunControlToolset.kt:25-26`).

get_test_results contract, copied:
- `get_test_results(executionId: Long? = null, configurationName: String? = null, testName: String)`. Read-only hints. It resolves the descriptor the same way as `get_run_output`.
- `testName` matches a leaf's `<suite>.<name>` exactly, or else the leaf's `name`.
- The reply has: a header line with the qualified name, status and duration; `message:` with the full error message; `stacktrace:` with the full stack trace; `output:` with the test's own console text, from `printOwnPrintablesOn` with a `StringBuilder` `Printer`.
- The reply is capped at `MAX_OUTPUT_CHARS`. When text is cut, the tail is kept.
- Status strings: `missing_argument`; `not_found` (the run's tab is closed); `not_a_test_run`; `test_not_found: <name>`, with the first 20 failed or unfinished names as hints; `ambiguous_test: <name>`, with the matching qualified names.

Settled here for the tool:
- Factor the descriptor lookup of `get_run_output` (`RunControlToolset.kt:97-119`) into one private function both tools call, so the `missing_argument`, `not_found` and `ambiguous` texts stay identical.
- `not_a_test_run` when no `SMTRunnerConsoleView` is in `consoleChain` (see `RunControlToolset.kt:146`).
- Copy the hint annotations of `get_run_output` (`RunControlToolset.kt:86-87`). Read the tree on `Dispatchers.EDT`.
- Truncation: copy the tail-keeping pattern at `RunControlToolset.kt:166-171`.
- `Printer` is `com.intellij.execution.testframework.Printer`; implement only what is abstract and append printed text to the builder.
