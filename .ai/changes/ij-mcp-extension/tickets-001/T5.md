## Goal

A project service records the start, end and final test counts of each run. The `get_run_output` header shows `startedAt` and `finishedAt`.

## Non-goals

- No new tools (`list_run_history` is Phase 5, `wait_for_run` Phase 4).
- No change to the failed-test block of `testSummary` beyond moving the counting out (Phase 3 replaces it).
- No edits to `RunHistory.kt`; T4 owns it.
- No platform fixture tests.

## Context

Plan: "Phase 2 > 3. Project service and listeners" and "4. Timestamps in the run header", plus "Public API Constraint" (no `.impl.`, no `@ApiStatus.Internal/Experimental` members; T1 made `verifyPlugin` fail on them). Read `src/main/kotlin/pl/mario/intellij/mcp/RunHistory.kt` (T4) for `RunStore`, `RunRecord`, `TestCounts`, `formatInstant`.

Contract, copied from plan.md:
- `@Service(Service.Level.PROJECT) class RunHistoryService` wraps one `RunStore`.
- `class RunHistoryExecutionListener(project: Project) : ExecutionListener`:
  - `processStarted` calls `started(env.executionId, env.runProfile.name, now)`.
  - `processTerminated` calls `terminated(env.executionId, exitCode, now)`.
- `class RunHistoryTestListener(project: Project) : SMTRunnerEventsAdapter()`. Its `onTestingFinished(root)` finds the open descriptor whose `processHandler === root.handler`, then stores `TestCounts` for that descriptor's `executionId`.
- The counting logic moves out of `testSummary` into one shared function, so the store and the tools count the same way.
- `plugin.xml` registers both classes under `<projectListeners>`, with `topic="com.intellij.execution.ExecutionListener"` and `topic="com.intellij.execution.testframework.sm.runner.SMTRunnerEventsListener"`.
- The `runOutput` header line becomes `executionId=…, name=…, state=…, startedAt=<iso|unknown>, finishedAt=<iso|unknown|->, console=…`. A running process shows `finishedAt=-`. The `get_run_output` `@McpDescription` names the new fields.

Settled here:
- Put the service, both listeners and the shared counting function in `RunHistoryService.kt`. The function is `internal fun countTests(root: SMTestProxy): TestCounts`. Move the rules from `testSummary` (`RunControlToolset.kt:184-195`): leaves are `isLeaf && !isSuite`; ignored is checked before `isDefect`; `other` = total - ignored - failed - passed; `finished = !root.isInProgress`. Keep the comment about ignored tests. `testSummary` then uses `countTests` for its counts line, with the same text as today.
- Get the service with `project.service<RunHistoryService>()` (`com.intellij.openapi.components.service`). Time is `System.currentTimeMillis()`.
- `onTestingFinished` can arrive off the EDT. Read `RunContentManager.getInstance(project).allDescriptors` on the EDT (for example `ApplicationManager.getApplication().invokeLater`). Skip the store write if no descriptor matches. Do not use `root.executionId`; it is often 0 (plan.md Key Discoveries).
- `env.executionId` is the same id as `RunContentDescriptor.executionId` (plan.md Key Discoveries).
- Header (`RunControlToolset.kt:145`): look up the record by `descriptor.executionId`. `startedAt = formatInstant(record?.startedAtMillis)`. `finishedAt` is `-` while the handler is not terminated, else `formatInstant(record?.finishedAtMillis)`. The `state=` text keeps today's values (`:136-142`).
- Register `<projectListeners>` in `plugin.xml` beside the `<extensions>` block at `plugin.xml:12`.

Decisions:
- The service exposes the store as a public `val store` instead of delegating methods; the plan says only "wraps one RunStore".
- finishedAt is "-" only when a handler exists and is not terminated. A null handler (state=unknown) shows formatInstant(record?.finishedAtMillis), so it never claims "running".
- Counts are taken in the onTestingFinished callback thread, before invokeLater, so a later change to the tree cannot alter them. Only the descriptor lookup and store write run on the EDT.
- testSummary keeps its own failed-test list (leaf, not suite, not ignored, isDefect) for the failed block, because TestCounts holds only numbers. Phase 3 replaces this block.
- SMTRunnerEventsAdapter and SMRootTestProxy.getHandler() checked with javap on idea-2026.2.3: public, no @ApiStatus or @Deprecated.
Open: Manual Phase 2 checks 2.6-2.8 in runIde (real timestamps, startedAt=unknown for a run started before plugin load, rerun behaviour) are not done; they need a human.
