## Goal

`RunHistoryTestListener.onTestingFinished` stores the final test counts also while a modal dialog is open. Its `invokeLater` runs with `ModalityState.any()`.

## Non-goals

- No other change to `RunHistoryService.kt`: the listener body, `countTests` and the execution listener stay as they are.
- No edits to `RunHistory.kt`, `RunControlToolset.kt` or `RunWait.kt`.
- No new tests: the listener needs the platform, and platform fixture tests are out of scope.

## Context

Source: T6 Follow-up 2 (reviewer T6) and the board Decision of 2026-11-04: "Phase 4 gets a fix ticket before wait_for_run: test-listener invokeLater uses ModalityState.any() (RunHistoryService.kt:47)."

Why: the default modality delays the `testsFinished` write while a modal dialog is open. `wait_for_run` (T11) reads counts from the store, so it must not see a stale record.

Where: `src/main/kotlin/pl/mario/intellij/mcp/RunHistoryService.kt:47`, `ApplicationManager.getApplication().invokeLater { ... }` inside `onTestingFinished` (:43). Pass `ModalityState.any()` as the second argument to `invokeLater`. Import `com.intellij.openapi.application.ModalityState` (public API).

The block only reads `RunContentManager.allDescriptors` and writes the synchronized `RunStore`; it opens no UI, so `any()` is safe here. Keep the `project.isDisposed` check.
