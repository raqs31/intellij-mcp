## Goal

`wait_for_run` blocks, within its own deadline, until a run (also one another caller started) has fully ended, then returns the `get_run_output` summary.

## Non-goals

- No event subscription; the tool polls.
- No `startedAfter` or "wait for the next run" mode.
- No edits to `RunWait.kt`, `TestTree.kt`, `RunHistory.kt` or `RunHistoryService.kt`.

## Context

Plan: "Phase 4 > 2. wait_for_run tool", "Implementation Approach" and "Critical Implementation Details". Read `RunWait.kt` (T10: `waitVerdict`, `clampTimeout`, `WaitVerdict`), `TestTree.kt` (T7: `TestsDetail`), `RunHistoryService.kt` (T5/T8: the service and its `RunStore`).

Contract, copied:
- `wait_for_run(executionId: Long? = null, configurationName: String? = null, timeoutSeconds: Int = 300, tests: TestsDetail = problems, tailLines: Int = 200, grep: String? = null)`. Read-only hints.
- The target is resolved once. By name, it is the newest descriptor at call time.
- The tool polls every 500 ms on the EDT until the verdict is not `WAIT` or the deadline passes. Between polls it calls `delay` outside the EDT, so the EDT is never blocked.
- `timeoutSeconds=0` checks once and returns at once.
- The grace clock uses the store's `finishedAtMillis`. If the store has none, it uses the time this call first saw the process end.
- The reply is `runOutput(…)`, with a final line `wait: done after <n>s`, `wait: timeout after <n>s` (the header then shows `state=running`) or `wait: test tree not finished <grace>s after process end`.
- A clamp adds `wait: timeoutSeconds clamped to 1800`.
- If the tab closes during the wait, the reply is built from the store record: `tab_closed: executionId=…, state=terminated, exitCode=…, startedAt=…, finishedAt=…` plus the stored counts.
- Argument errors use the same status strings as `get_run_output`.
- The `@McpDescription` says that the call returns at once when the run already ended, and that `finishedAt` shows when.

Settled here:
- Resolve the target with the shared descriptor lookup T8 factored out of `get_run_output`, then keep only its `executionId`. Each poll re-finds the descriptor by that id in `RunContentManager.allDescriptors` on `Dispatchers.EDT`.
- Validate `grep` as `get_run_output` does (`invalid_regex`).
- Poll inputs: `processEnded = handler.isProcessTerminated`; `hasTestTree` = an `SMTRunnerConsoleView` is in `consoleChain`; `treeFinished = !resultsViewer.testsRootNode.isInProgress`.
- The JetBrains MCP server puts no timeout on a tool call, so this deadline is the only limit. Use `delay(500)` on the caller's dispatcher, never on the EDT.
- `clampTimeout` sets the clamp line. A negative value clamped to 0 counts as clamped but the plan names only the 1800 line; print `wait: timeoutSeconds clamped to <value>`.
- Stored counts in `tab_closed`: the `tests: total=…` line in today's shape (use `TestCounts`), or no line when the record has none.
